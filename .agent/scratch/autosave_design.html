Auto-Save Design Visualization

1. State Diagram

Transitions between system states during the auto-save lifecycle.

                stateDiagram-v2
                    [*] --> IDLE
                    IDLE --> DIRTY : User Action (Brush/Grid/Command)
                    DIRTY --> DIRTY : Additional Action (Reset Debounce)
                    DIRTY --> SAVING : Debounce Timeout (10s)
                    DIRTY --> SAVING : Fallback Timeout (60s)
                    SAVING --> IDLE : Save Success / Reset Dirty
                    SAVING --> DIRTY : Action during save
                    IDLE --> IDLE : Ctrl+S (Manual Save)
                    DIRTY --> IDLE : Ctrl+S (Manual Save)

                    DB -->|Trigger| SV[Save Executor]

3. Timing Logic

Debounce (10s)

Resets on every action. Ensures we only save when the user stops working for a moment.

Fallback (60s)

Fixed period from the FIRST dirty change. Ensures data is safe even during intense, non-stop work.
